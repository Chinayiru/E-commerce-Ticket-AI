# 补充 AI 审查：代码、断言与评估独立性

审查日期：2026-11-05（Asia/Shanghai）。结论：现有数字不足以支持独立泛化或客服采纳主张；现有 AC 测试没有覆盖全部合同要求。原实现者同时编写代码、规则、验收断言、数据和初筛评分，是交付的主要结构性风险。当前新增的是一次补充 AI 代码阅读和对抗探针，**不是第二人或客服复核签字**，也不能为旧 holdout 恢复独立性。

## 证据与边界

阅读重点包括 `core/loop.py`、`policy.py`、`hooks.py`、`context.py`，工具注册表与业务/动作工具，存储、模型协议、OpenAI 兼容 Provider、HTTP/CLI、评估与 AC01–AC21。并非形式化验证或完整安全审计，未做真实网络断连、真实模型复跑或生产流量测试。

复现入口：`python scripts/review_probes.py`。12 项探针均复现审查问题，退出码 1 是“仍有问题”的结果，不是探针执行崩溃；见 [原始结果](review-probes-2026-11-05.json)。其中 R01、R05 各拆为两项探针，所以是 12 项探针、10 组发现，不能把它算成 12 条独立业务样本。

探针使用自行构造的开发反例、假 Provider 和临时 SQLite，不加载旧评估集、不调用远端、不修改业务规则。临时库结束后清理，JSON 保存观测输出与被审查文件 SHA-256；其中 run_id 只关联该次临时运行，不代表仍可查询的持久 trace。探针文本已经暴露，今后只能作开发/回归材料。

## AC01–AC21 逐项核对

“覆盖”只指已读测试中的断言强度，不是再次宣布合同验收完成。多项桩回复由 `app/eval/scripted_cases.py::final_step` 从同一标注生成；转人工值及原因可能在模型桩中已经正确，不能证明策略独立修正错误模型输出。

| AC | 已有断言 | 未证明的合同部分/建议 |
| --- | --- | --- |
| AC01 | 状态、意图、工具集合、58.00 字样、无 refund_submit | 回复来自已知样本；未证明金额事实守卫、真实副作用快照和缺证据场景，见 R03 |
| AC02 | 原因、转人工、草稿无 U002 | 没断言他人金额/状态/运单在全部响应及原 trace 中均不泄露 |
| AC03 | refund_submit 被拦、入口 approved 被拒 | 没测动作 arguments 的 approved、address_change；优先级不符，见 R07 |
| AC04 | 缺号、歧义、批量原因与部分无工具断言 | 无歧义/非批量的相邻反例、全部优先级组合不足 |
| AC05 | 七条原因、需人工、非空草稿、无业务写操作 | 部分原因由桩直接提供；没断言每条持久化及策略对错误桩的纠正 |
| AC06 | 两条审计、缓存标志、幂等键为空 | 基本重复调用路径有覆盖；未用计数器独立证明 handler 第二次未执行 |
| AC07 | 两次答案/工具名相同、第二次非缓存 | 同库重跑有覆盖；没有完整比较 tool ok、原始事实和跨样本同日冲突 |
| AC08 | 直接开两个 loop 线程得 200/409 | 非真实并发 HTTP；线程结束后 running≤1，不等于运行中唯一性/其他完整性错误分流已验证 |
| AC09 | 循环后步数/token/假时钟超限 | 没覆盖超限终局、悬挂 HTTP 和重试 deadline，见 R05 |
| AC10 | 注入缺 usage、直接抛 InvalidModelOutput | 未覆盖真实响应 JSON/部分 usage 结构及完整计费分母；Provider 解析边界另需核验 |
| AC11 | record_tool_call 抛错得到 HTTP500 | 其他持久化阶段和内部工具失败未覆盖，见 R09 |
| AC12 | 完整消费 SSE、末尾单个终止事件；另测假时钟 | 没真正中途断开网络、没有验证 client_disconnected 与无残留 running |
| AC13 | 手工脚本重放、source_run_id、未知 replay_snapshot | 未验证 CLI frozen/fresh 两种模式与真实快照；当前 CLI 只有脚本式 replay |
| AC14 | 两轮意图/工具名相等、第一轮无降级 | 没比较全部逐条评分、参数、转人工及第二轮降级；旧评分本身有 R01/R02 |
| AC15 | HTTP trace 不含指定手机号及任意 11 位数字 | 漏测落库与日志，且随机 ID 会误报，见 R08/R10 |
| AC16 | 恰 200 与超限样本的转人工结果 | 已有固定金额边界；缺配置变化、错误模型结论与独立事实校验 |
| AC17 | 七天/超期两个已知样本 | 缺精确截止±微秒、签收时间缺失及 query/preview 时间判定一致性 |
| AC18 | 未发货/已发货最终不转人工 | 没断言 NOT_SHIPPED 发生一次或禁止重复查询，单靠结果不能证明流程 |
| AC19 | 含保证/赔偿的一个草稿被替换 | 未覆盖无该关键词的执行成功声称、纯时限承诺、否定句，见 R03 |
| AC20 | 注入 UpstreamError 得503、有 trace | 没通过假 HTTP 客户端验证401/403不重试与5xx重试耗尽、预算和时间 |
| AC21 | 一个投诉样本、无工具、步数和草稿词检查 | 未覆盖 JSON 修复后的预检、否定/引用投诉词与优先级冲突 |

额外 `test_holdout_runs_offline` 使用的是已经公开、反复离线跑的旧文件；只作回归冒烟。不能依据“真实模型仅跑一次”把它称为独立未见集。

## 后续交付门槛

先处理事实/订单绑定、存储脱敏、旧评分和预算等高影响问题；每一项用独立构造的失败先行反例验证，不能只调整已有 gold 或正则使固定样本得满分。修复人和复核人/流程分别留身份、版本和证据。

再按 [新盲测流程](../docs/BLIND_EVAL.md) 冻结候选，外部出题与全量标注复核，封存 12 条并由保管方运行。新流程已实现、离线测试已通过，但新独立样本与成绩尚未产生。12 条即使独立，也只支持小样本合成业务结论，不直接等于线上总体泛化率。

`drafts_50` A=30/50 只读作实现者自查通过率 60%。客服采纳率必须由独立业务复核后另报，不由这里的探针数、自动评分或流程测试补齐。
