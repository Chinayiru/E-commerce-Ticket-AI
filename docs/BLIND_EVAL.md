## 角色与交接

实现者完成修改后冻结候选，不接触新题目或标签。独立出题方只收到 [出题合同](BLIND_AUTHOR_CONTRACT.md)、合成订单表与冻结配置；另一独立人员或隔离流程在运行前复核全部标注。保管方控制仓库外的样本、封存记录、凭据和运行输出，执行字面及语义去重，并运行一次测试。业务复核方另评草稿，不能由脚本 A 档替代。

“隔离流程”须有不同的干净上下文和可留档的输入记录；不能继承实现对话、源码、旧题或旧失败。使用同一家模型并不等于第二人复核，应如实标明模型和流程标识。身份不同、没有接触旧题以及语义去重属于外部事实，脚本只能校验声明，不能证明其真实性。

本次审查存在待修问题，见 [补充审查](../reports/review-2026-11-05.md)。建议先修复并验收，再冻结拟对外报告的候选。冻结前可以调开发集；冻结后任何源码、运行时或配置变化都需要新候选和未暴露的新样本。审查探针属于开发反例，不能充当新盲测。

## 可执行步骤

以下命令在项目根目录运行。路径是操作示例，本轮没有创建其中的题目、封存或真实调用。工作目录必须在仓库外，由保管方管理权限；仅把文件放在另一个目录不会自动形成隔离。

1. 实现者把 `docs/blind-config.example.json` 复制为保管方持有的配置，填好实际模型与代理地址。`base_url` 不得含凭据；凭据只通过保管方运行环境的 `OPENAI_API_KEY` 提供。配置必须含例子中的全部键；价格是估算输入，不能当作供应商已核实价格。
   在接触新盲测前，用公开开发工单确认账户、模型和连接可用；不能拿新题目试网络再重新跑。脚本会拒绝 URL 中的凭据和查询参数。
2. 冻结源码、评分脚本、验收测试、设计合同、模型配置与 Python/依赖版本；输出作者包。

```powershell
python scripts/blind_eval.py freeze --work 'H:\盲测保管\candidate-001' --config 'H:\盲测保管\config.json' --implementer '实际实现者或实现流程标识'
```

作者包只包含 `author-contract.md`、`mock-orders.json` 与 `candidate.json`（文件哈希、配置和环境，不含代码或提示词正文）。保管方只转交这三份材料给出题方及标注复核方，不把审查报告或整个仓库一起交出。

3. 独立方编写新的 `cases.jsonl` 并完成全量复核。保管方检查语义重复和来源记录，填写独立性声明。初始值保持 false；只有实际完成后才改 true。

```json
{
  "author": "实际出题人或干净流程标识",
  "label_reviewer": "另一实际复核人或隔离流程标识",
  "custodian": "实际保管方标识",
  "independent_from_implementer": false,
  "no_candidate_code_or_old_cases_seen": false,
  "implementer_has_not_seen_new_cases": false,
  "semantic_overlap_reviewed": false
}
```

其中 `no_candidate_code_or_old_cases_seen` 指出题和标注复核方；保管方为去重可访问旧题，但不能回传旧题或失败信息。所有身份和声明必须真实，换一个名字不构成独立性。

4. 保管方封存，先校验 12 条、四类各 3 条、字段、全量确定标签、工具参数一致性以及旧题字面去重。封存结果含数据 SHA-256、候选 SHA-256 和独立性声明，不输出题干。

```powershell
python scripts/blind_eval.py seal --work 'H:\盲测保管\candidate-001' --dataset 'H:\盲测保管\cases.jsonl' --attestation 'H:\盲测保管\attestation.json'
```

5. 保管方配置凭据后运行。此命令会产生真实模型费用；本轮只验证了替身流程，没有执行它。

```powershell
python scripts/blind_eval.py run --work 'H:\盲测保管\candidate-001' --dataset 'H:\盲测保管\cases.jsonl'
```

调用前以排他创建方式写入 `attempt.json`，同一工作目录再次运行会被拒绝；故障也消耗这次尝试，不支持从失败点恢复后挑选结果。底层被测 Provider 的固定单次请求重试、JSON 修复属于被冻结的系统行为，不等于重跑评估。源码、运行时或数据指纹变化会拒绝运行；结束时再次核对源码。

`results.jsonl` 逐条追加、`runs.db` 保存原始轨迹，`report.json` 保存全量统计；中断时保存 `failure.json`，不得把已完成子集的分数冒充 12 条成绩。原始数据库和回复可能含敏感字段（已在本次审查中发现存储脱敏缺陷），由保管方持有并使用合成数据。实现者只在报告封存后获知结果；任何题目或失败暴露后，该批数据退休为回归资料。

## 评分与结论范围

新流程的 `score()` 不调用已有 `app/eval/metrics.py`，避免继承本次发现的评分缺陷。

- 四项指标均以 12 为分母，报告正确条数、比率及 Wilson 95% 区间；无答案、非正常结束都记失败，不动态排除标签。
- 工具集合必须完整相等。参数必须有调用明细，所有预期调用有匹配，所有实际调用有匹配，拒绝额外错误参数和审批拦截。订单号只做去首尾空白和大写规范化，其他值保持原样。
- 预期业务错误须在运行前写入每个调用的 `error_code`；技术异常不得临时加进白名单。预期无权查询被拦截时，只代表符合标注，不代表订单查询成功。
- 转人工同时核对布尔值和原因，另报 TP/FP/FN/TN 与缺答案数。草稿语义、事实一致性和客服采纳率需独立人工评定，四项自动指标不会覆盖这些质量。
- 12 条均衡合成数据只能支持该范围内的小样本结果，即使独立也不能直接声称线上泛化率。置信区间基于二项近似，不能消除人为选样偏差。

## 流程边界与复现

脚本防止常见误操作，不是抵抗实现者篡改的安全系统：有写权限的人仍可删掉消耗记录、另建目录或伪造声明。保管方须限制实现者访问，保存候选/封存哈希与尝试记录的外部副本，统一登记已使用数据指纹，禁止换目录重复使用数据。环境指纹记录 Python 与主要依赖版本，不封装操作系统、模型服务端版本或完整依赖镜像；正式报告另附这些环境限制。

```powershell
python -m pytest tests/test_blind_eval.py -q
python scripts/review_probes.py
```

第一条测试使用合成占位工单和假 Provider，验证冻结、封存、标签隔离、失败与防重跑；这些工单不是新的盲测。第二条用于复现业务审查问题，有问题时退出码为 1。两者都不能作为模型能力或客服复核成绩。

## 同条件三次比较（开发集基线/候选的读数纪律）

封存新题是一次性的，开发集上仍要回答“这次改动到底稳不稳”。为此新增 `scripts/compare_runs.py`，
把“各跑 3 次、报原值/中位数/范围”从口头纪律变成会失败的检查：

```powershell
python scripts/compare_runs.py --arm baseline=reports/b1.json,reports/b2.json,reports/b3.json `
                               --arm candidate=reports/c1.json,reports/c2.json,reports/c3.json `
                               --out reports/compare-$(Get-Date -Format yyyyMMdd).md
```

它拒绝的四种情况（不是建议，是退出码非 0）：

- 任一臂少于 3 次运行（不补跑就不给结论）；
- 两臂或组内混用不同 `dataset_hash`；
- `provider`/`model`/`max_steps`/`wall_clock_s`/`window_turns`/`demo_now`/`token_budget` 不一致；
- 只有“结果不同”没有逐例明细——逐例判定不一致的 case 会全部列出，不被中位数掩盖。

输出结论固定附一句“中位数差值不等于统计显著性”。n=3 能证明的是**是否稳定复现**，不是提升；
要声称提升需要更大样本、独立数据集，或至少 5 次且范围不重叠。`tests/test_compare_runs.py` 用合成报告锁定上述四种拒绝行为。
