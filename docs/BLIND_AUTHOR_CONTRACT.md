# 新 12 条盲测的出题合同（可单独交给独立出题流程）

本文件只规定产品行为与标注格式，不含旧样本、候选提示词、候选实现或失败记录。出题方只能收到本文件、冻结后的非敏感配置、合成订单表。保管方另行核对与旧样本的字面及语义重复，不把旧题提供给出题方。

任务：中文电商售后工单，输出四类意图、草稿和是否需要人工处理。只读查询合成订单及物流、预览退款；不执行退款或改地址。范围限于订单表与演示时间所定义的合成业务。

## 样本设计

恰好 12 条，每个意图 3 条；由出题方自行选择自然表达、诉求和订单组合。不要照着旧样本改写，不依据候选模型的回答确定标签。至少包含正常处理、需核实或转人工两种行为；覆盖面由独立出题方记录，12 条不能代表线上分布。

- `refund`：退款或退货退款。
- `address_change`：变更收货地址或收货信息。
- `shipping_urge`：发货、物流进度和签收事实咨询。
- `other`：上述之外的咨询，或明确跨订单/投诉类工单；跨意图存在歧义时，由标注复核方在运行前裁定并写明理由，不能看输出后改标签。

订单事实由 `mock-orders.json` 提供；订单号格式 `O` 加四位数字。每条工单绑定输入 `user_id`；不存在或属于其他用户的订单统一视为 `ORDER_NOT_FOUND`，不得返回他人事实。订单事实、金额和时间均不能自行捏造。使用 `candidate.json` 的演示时间和阈值，不使用出题当天墙钟判定售后期。

## 工具与策略

可评分的只读工具为 `query_order`、`check_logistics`、`refund_preview`，均只接受 `{"order_id":"有效格式的订单号"}`。需要订单事实才能答复的工单应查询相应工具；工具集合按完整集合评分。程序内部保存草稿不纳入业务工具集合。

退款工单应查订单和退款预览。未发货且金额不超过冻结配置阈值时可预览；恰好等于阈值仍在范围内。已发货退款需人工，优先于金额条件；已签收退款须结合售后期，恰好到截止时刻仍在期内，超过截止时刻需人工。退款预览不表示款项已经退回。

物流工单需要订单及物流事实；未发货查询物流返回 `NOT_SHIPPED`，这一单次业务状态不等于工具技术故障。改地址先查订单，所有改地址均转人工，不调用实际改地址动作。

预检优先级：投诉/法律威胁 → 明确跨多订单处理 → 订单候选冲突 → 必需订单却缺号。预检命中即转人工，不查询业务工具，对应原因依次为 `COMPLAINT_OR_THREAT`、`MULTI_ORDER`、`AMBIGUOUS_ORDER_ID`、`MISSING_ORDER_ID`。

终局优先级：非正常终止 → 动作被拦 → 订单无权/不存在 → 连续工具技术失败 → 已发货退款 → 金额超限 → 售后超期 → 改地址 → 签收争议 → 低置信/草稿风险/其他模型请求。对应业务原因包括：

| 条件 | 原因 |
| --- | --- |
| 订单无权或不存在 | `ORDER_NOT_FOUND` |
| 连续技术失败至少两次 | `TOOL_FAILURE` |
| 退款且已发货 | `REFUND_AFTER_SHIP` |
| 退款金额超过阈值 | `REFUND_OVER_LIMIT` |
| 退款超过售后截止 | `REFUND_NOT_ALLOWED` |
| 地址互相冲突 | `ADDRESS_CONFLICT` |
| 已发货改地址 | `ADDRESS_AFTER_SHIP` |
| 其他改地址 | `ADDRESS_CHANGE` |
| 无赔偿/追责诉求的签收事实争议，意图为 shipping_urge | `DELIVERY_DISPUTE` |

签收争议须由语义判断，不按候选正则或关键词反推标签。否定、引用、纠正与真实争议应分辨。赔偿/追责诉求的意图及原因由复核方依据投诉优先规则运行前裁定。

仅选择能在运行前确定 `needs_human` 与原因的条目。信息类咨询若只能靠候选模型自报置信度决定是否转人工，则不适合本次固定标签盲测；应替换题目，或另设不计入这 12 条的探索性记录。不得运行后排除样本。

草稿须与已查询事实一致，不编造执行成功、金额或时限，不做赔付保证，不泄露敏感字段。草稿的客服可用性另由独立业务复核方评分，不由本次四个自动指标代替。

## 数据格式

交付 UTF-8 JSONL，每行一个对象，只含下列字段，不附模型脚本或参考回复：

| 字段 | 要求 |
| --- | --- |
| `case_id` | 唯一，6–40 位英文字母、数字、下划线或短横线 |
| `user_id` | 非空字符串，合成用户 |
| `text` | 非空中文工单，最多 2000 字符 |
| `order_id` | 结构化订单号或 null；格式 O 加四位数字 |
| `intent` | 四个意图之一，每类三条 |
| `expected_tools` | 业务工具名称数组，不重复；预检或无需工具时为空 |
| `expected_args` | 数组；每项恰含 `name`、`arguments`、`error_code` |
| `expected_needs_human` | 必须为布尔值，禁止 null |
| `expected_reason` | 转人工时为确定原因，其他为 null |
| `label_reason` | 运行前写明标注意图、工具、转人工原因的依据 |

`arguments` 恰含 `order_id`。`error_code=null` 表示期望调用成功；允许的预期业务错误为 `NOT_SHIPPED`、`ORDER_NOT_FOUND`、`REFUND_NOT_ALLOWED`、`ORDER_STATE_UNSUPPORTED`。这使“预期无权订单查询”可单独评分；`args_ok` 只说明调用符合盲测标注，不能解释为业务成功或没有权限拦截。

一位独立作者出题，另一位独立人员或隔离流程复核全部 12 条标注；分歧须先裁定，再封存文件。出题和复核均不得看到候选代码、提示词、旧样本和旧报告。保管方可接触旧样本以检查重复，但不得把它们或旧失败反馈给出题方。
