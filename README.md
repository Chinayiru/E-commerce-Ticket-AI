## 快速开始

```bash
# 0) 依赖：Python 3.12+，pip install fastapi uvicorn httpx pytest
# 1) 验收（AC01–AC21，离线，不需要 API Key）
$env:PYTHONPATH='.'; python -m pytest tests -q          # 原22项验收 + 17项盲测流程；AC15有已知随机误报，见审查

# 2) 跑一条工单（scripted：这里用脚本替代模型）
python -m app.cli run --ticket-id t-000001 --user-id U001 \
  --text "订单 O1001 一直没发货，帮我退了" --order-id O1001 \
  --script scripts/demo_script.json

# 3) 看 trace（四张表 + 逐步事件）
python -m app.cli trace <run_id>

# 4) 评估与证据
python scripts/seed_datasets.py         # 24 / 12 / 50 条数据集
python scripts/run_eval.py --out reports
python scripts/check_leakage.py         # 题干泄漏检查（ok=true 才算过）
python scripts/collect_evidence.py      # 生成 reports/evidence-index.md

# 5) HTTP / SSE
python -m app.cli serve --port 8000
#   POST /v1/tickets  GET /v1/runs/{run_id}  POST /v1/tickets/stream
```

`provider=scripted` 的数字只证明“循环、工具、落库、策略、验收链路是通的”，
不代表模型能力；真实模型需要 `OPENAI_API_KEY`（可选 `OPENAI_BASE_URL`）后
`python -m app.cli eval --provider openai`。

## 六组件：一组件一文件，禁止跨层直连

下表是实际布局（`app/` 下按组件分文件，跨层直连被检查项约束）：

| 组件 | 目标文件 | 它唯一负责的事 | 它不许做的事 |
| --- | --- | --- | --- |
| E 执行循环 | `app/core/loop.py` | 有界 while：校验 → 路由 → 选工具 → 调工具 → 判断继续；累计 token 与时钟 | 直接拼 SQL、直接 import 工具实现、做业务规则判断 |
| T 工具注册表 | `app/tools/registry.py` | `@tool` 反射生成 JSON Schema；参数校验；异常转结构化错误 | 抛异常给调用方、接受未知参数、在工具里 sleep |
| C 上下文 | `app/core/context.py` | 保留最近 6 轮原文，更早折叠成 6 字段确定性摘要 | 用向量检索、让模型写摘要、截断 `role=tool` |
| S 状态 | `app/store/db.py` | 恰好 4 张表；按 `run_id` 取回完整 trace | 建第 5 张表、在存储层写业务判断、静默吞写入异常 |
| L 钩子 | `app/core/hooks.py` | 工具前后拦截：审计、打点、不可逆转人工、脱敏 | 把拦截逻辑散落在钩子之外、记录未脱敏手机号 |
| V 评估 | `app/eval/` | 24 条确定性集 + 50 条草稿集；跑批、回放、版本对比、报告 | 手改数字、用测试集调参后宣称泛化、桩数据混进模型指标 |

配套模块：`app/schemas.py`（契约）、`app/core/policy.py`（转人工策略层，**覆写**模型结论）、
`app/core/prompts.py`、`app/tools/business.py` + `actions.py`（6 个工具）、
`app/llm/`（Provider 协议 + OpenAI 兼容 + 离线桩）、`app/cli.py`、`app/api/main.py`。
完整职责与禁止项见 [docs/DESIGN.md](docs/DESIGN.md) 第 5 章。

## 三个必答问题（成稿）

### 1. 为什么不用 LangGraph

工单处理的拓扑是**一条主线 + 三条分支**：查订单 → 按意图分支（退款预览 / 物流 / 改地址）→ 出草稿。
这不需要图调度器，需要的是"什么时候必须停"。

有界 `while step < max_steps` 把"停"写成三个可测数值：步数 6（典型路径预估3次模型请求 + 1次纠错 + 2步余量，实际路径待验证）、
token目标6000（调用前估计、调用后核对usage，不能宣称跨供应商精确硬上限）、墙钟 30 秒（覆盖上游悬挂——此时步数不涨、token 也不涨，
只有时钟兜得住）。三者不可合并，因为它们覆盖的故障态互不包含。

框架能换来并行子图、跨天人工挂起、检查点恢复——本项目一个都不需要；
代价是多一层抽象、trace 里多一层框架事件、面试时说不清"这一步是谁决定的"。
**结论：可控性优先于表达力。** 什么时候会换：出现真正并行的子任务或跨天挂起时（见 DESIGN.md ADR-001）。

### 2. 上下文怎么裁剪

同一run内部短执行链 + 结构化状态，所以设计为**滚动窗口 + 确定性摘要**，不用向量检索：

- 保留最近 `WINDOW_TURNS=6` 轮原文；
- 更早的折叠成 6 个固定字段：`intent_history`、`slots`（覆盖写）、`tools_called`、`last_decision`、
  `open_questions`、`need_summary`；
- 折叠时跳过 `role=tool` 边界，工具调用与结果不会被切开；
- 摘要是纯函数，同输入必得同输出——回放要确定性。

不用向量检索的三个理由：① 当前仅单run内部模型/工具轮次，不支持用户会话接续；② 状态需要**覆盖写**（地址从家改到公司），
相似度召回会同时捞回旧地址；③ 检索增加调用或维护成本，当前缺少必要性；具体费用需实测。
换方案的触发条件写死在文档里：超过 20 轮或需要跨工单引用会员历史时再评估。

### 3. Bad Case 怎么闭环

trace 记四件事：用了哪个工具、参数是什么、上下文里有什么、模型原样输出是什么——缺一条就无法归因。

归因只有四类语义失败，参考修复顺序 **A → C → B → D**；越权、安全和基础设施故障优先处理：

| 归因 | 判定 | 为什么在这个位置 |
| --- | --- | --- |
| A 意图识别错 | 意图与标注不一致 | 后面全错，修一条顶三条 |
| C 参数提取错 | 工具对、参数不符 | 会让结论指向错误事实，风险最高 |
| B 工具选错 | 意图对、工具集合不等 | 只影响信息完整度 |
| D 草稿质量差 | 前两者对、草稿缺要素或越权承诺 | 不影响业务动作，但决定采纳率 |

修复后用 `replay --run-id <失败run> --prompt <新版>` 重跑同一条工单，比对改前/改后的意图、工具集合、转人工判定；
再跑24条开发回归集确认影响，报告正确和失败条数。冻结离线回归少1条即退化；真实模型需复跑并记录采样波动。

一条历史参考实现叙述（见BADCASE.md，当前缺实现、trace及报告附件，未经本轮核验，不作为个人实测证据）：
第二次跑评估时参数正确率从 87.5% 掉到 4.2%，trace 显示工具集合正确却报"未被调用"。
根因是幂等键做了全局唯一索引，同日第二次评估写审计行时撞唯一约束，被
`except sqlite3.IntegrityError: return False` 静默吞掉。修复为 `UNIQUE(session_id, idempotency_key)`、
缓存查询按 run 过滤、缓存命中也落审计行，并加回归测试锁定。
**这条教训已升级为设计契约：幂等键不得全局唯一。**

这**不是代码缺陷**，是默认预算与推理型模型不匹配（思考 token 计入输出、单步常见 2k）。文档默认值不改，部署时按模型类型调高并写进报告条件。


**以下限制必须与数字一起读**：

1. 开发集满分里有自证成分——`delivery_dispute` 规则是为了满足我先前写下的 24 条标注才加的，开发集 100% 不能当泛化证据；
   旧 holdout 由同一实现者生成、读过文本并运行过；“真实模型只跑一次”不能证明独立性。0.9167/1.0000/1.0000/0.9167 仅是历史观测，不能作为独立泛化证据；后续调参不得继续把它当盲测。
2. 转人工准确率分母排除了 2 条“信息类咨询”标注（`expected_needs_human=null`，转不转人工取决于模型置信度）。
   分母是 22 而不是 24，这一点在报告里显式给出，不做隐性缩小。
3. AC01–AC21 的断言、`DELIVERY_DISPUTE` 规则、数据构造和初筛评分来自同一实现者，缺少第二人代码及业务复核。这是整套交付的主要结构性风险；测试通过不能替代独立验证。本轮新增的是补充 AI 审查，不是第二人或客服签字。
4. 补充审查（`scripts/review_probes.py`，12 条可执行反例）曾发现旧评分存在缺失调用明细、缺答案仍可能得分、越权调用仍算对等问题。本轮已按 R01–R10 全部修复（细节见 [BADCASE.md](docs/BADCASE.md) 第 9 节），探针 `reproduced=0`；表中数字是用修复后的严格度量重算的**新一轮**结果，不是历史报告的翻版。新独立样本与四项严格评分流程见 [BLIND_EVAL.md](docs/BLIND_EVAL.md)。

单次运行内的波动仍在噪声区间，任何“提升”需同条件重复 3 次取中位数才可宣称。
单条成本按 0.15/0.60 USD per Mtok、汇率 7.2 估算，**不是代理商的真实价格**；P95 含推理型模型的思考耗时。

| 指标 | 目标 | 当前状态 | 判定口径 |
| --- | --- | --- | --- |
| 实现者自查通过率（草稿 A 档） | 观察规则初筛结果，不预设提升 | 60%（30/50，**实现者规则初筛**，未做客服复核） | 固定规则的字面要素检查；不代表语义质量或客服采纳 |

三条数字纪律（违反任何一条，报告作废）：

1. 实测数字必须有原始报告和复现入口；阈值、规模和排期标为目标或计划。真实模型需能追溯实验条件，不承诺每次得分一致。
2. 离线桩（`scripted`）的数字只能标注 `provider=scripted` 出现，不得与模型数字混排。
3. 在 24 条或已暴露的旧 holdout 上调参只报告开发回归结果；新的 12 条须由独立出题/复核流程提供，先冻结候选与评分口径，再封存、运行并退役。独立小样本也不能直接代表线上总体。
